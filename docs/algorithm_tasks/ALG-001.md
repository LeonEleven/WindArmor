# ALG-001 — Basic Attitude Feedback / 基础姿态反馈

本文是 ALG-001 的独立 Task Spec。它定义单轴基础姿态反馈的软件能力和资格边界，不是候选
实现、真实执行器分配、硬件操作手册或硬件授权。共享接口仍以
[Flight Control API](../FLIGHT_CONTROL_API.md) 为准，统一验证规则见
[Algorithm Benchmark](../ALGORITHM_BENCHMARK.md)。

## 2. Objective

对有效且新鲜的 `state.imu.relative_pitch_rad`，围绕当前有效 IMU zero reference 的
`target_pitch_rad = 0 rad`，产生方向明确、没有非预期零点偏置、可重复且可解释的基础
proportional-style 姿态反馈意图。

ALG-001 只证明一个软件关系：姿态误差的符号和幅值变化能够产生确定的单轴反馈意图。它不
证明机器人能抗外力恢复平衡、判断运动趋势、消除振荡、处理真实动力学、完成最佳执行器
分配或进行多轴恢复。

## 3. 输入与继承边界

### 3.1 控制律输入

唯一允许进入 ALG-001 控制律的状态量是：

- `state.imu.relative_pitch_rad`，单位 rad。

以下量不得进入反馈计算：

- `angular_velocity_rad_s`、`linear_acceleration_m_s2`；
- roll、yaw 或任何自行推导的相对 yaw；
- fan feedback dynamics；
- recovery state、上一帧 pitch 或其他时序历史。

### 3.2 安全检查与合法命令所需输入

实现可以读取下列字段，但它们只用于输入安全检查、保持非控制轴或构造合法完整帧，不构成
新增控制能力：

- `state.imu.valid`、`state.imu.fresh`；
- `state.system.required_inputs_fresh`；
- `state.system.e_stop_active`，未知或非 `False` 时 fail-close；
- 全部必要电机的键、`position_rad`、`has_feedback`、`valid`、`fresh`、`healthy`；
- `dt`；
- 生成完整命令所必需但不参与反馈律的固定 candidate 配置。

普通命令若需要保持其它轴，只能基于同一合法状态/当前算法会话所捕获的完整电机位置形成
完整帧；缺失轴不能解释为保持上一命令。反馈值和 fixture 值都不是机械中位。

## 4. 单位、误差和软件符号

- pitch 和电机位置使用 rad；
- `dt` 使用本地单调时钟秒数；
- `target_pitch_rad = 0 rad`；
- `pitch_error_rad = target_pitch_rad - state.imu.relative_pitch_rad`。

因此：

```text
relative_pitch_rad > 0  -> pitch_error_rad < 0
relative_pitch_rad < 0  -> pitch_error_rad > 0
```

ALG-001 定义任务局部的抽象标量 `pitch_feedback_intent`。它使用无量纲的“software intent
unit”，正方向定义为与 `pitch_error_rad` 同号；其候选增益单位为 intent/rad。对于 Profile
v1 的线性场景，一个合格候选应满足：

```text
pitch_feedback_intent = Kp * pitch_error_rad
Kp > 0，且 Kp 为固定、有限、可追溯的 candidate configuration
```

`Kp` 的大小不是越大越好，本 Task Spec 不选择真实最优增益。候选可通过纯函数或等价的
无硬件测试 seam 暴露该抽象量；本任务不规定控制器类名或公开 API 变更。

### 4.1 软件符号不等于真实执行器方向

`pitch_feedback_intent` 的正负只属于软件反馈语义。它不能自动推导为：

- 某台电机正转、反转、增加或减少目标位置；
- 左风扇或右风扇增加；
- 某个风扇命令会产生目标方向的真实恢复力矩。

任何上述结论都需要独立机械审核、模型或实验依据，并属于 ALG-006 control allocation 或
后续受限硬件验证。教学控制器已有的 `left_pitch`/风扇映射也不得作为该依据。

## 5. Expected behavior

本节的“零容差”和比较容差均使用
[ALG-001 Profile v1](../ALGORITHM_BENCHMARK.md#7-alg-001-profile-v1) 定义的软件容差。

### Neutral

`relative_pitch_rad = 0` 时，`pitch_error_rad = 0`，抽象 feedback intent 必须在零容差内为
零，不得存在非预期姿态反馈偏置。

### Positive pitch

相同配置下，`relative_pitch_rad = +0.05 rad` 和 `+0.10 rad` 分别产生负的软件 feedback
intent。中等输入的绝对 feedback 必须严格大于小输入，且两者的
`feedback / pitch_error` 在比例一致性容差内相等。

### Negative pitch

相同配置下，`relative_pitch_rad = -0.05 rad` 和 `-0.10 rad` 分别产生正的软件 feedback
intent。幅值关系和比例一致性要求与 positive pitch 相同。

### Symmetry and consistency

Profile v1 的四个非零场景处于明确的基础线性区，要求近似奇对称：

```text
feedback(+x) ~= -feedback(-x), x in {0.05 rad, 0.10 rad}
```

“近似”按 benchmark 的 absolute/relative tolerance 客观判断。该要求只约束抽象软件 intent，
不要求真实执行器响应、推力或机器人动力学对称。

## 6. FlightCommand 与 control allocation 边界

公开控制器仍必须返回现有 `FlightCommand`；本任务不新增或修改 Flight API。资格验证分开
处理两个问题：

1. LEVEL A 从 candidate 的 task-local seam 取得 `pitch_feedback_intent`，评分 neutral、
   direction、monotonic magnitude、proportional consistency、symmetry 和 repeatability；
2. LEVEL B 调用 controller factory 和 `update()`，只验证状态/命令契约、完整电机帧、合法
   fan command、有限值和 safe-stop。

Profile v1 **不从** `motor_positions_rad` 或 `fan_commands` 反推抽象 feedback intent，也不对
某个真实电机/风扇方向评分；在 ALG-006 以前，这种物理方向指标为“当前不可评分”。候选为
形成合法预览而使用的 hold 或 task-local encoding 必须明确标为非生产、无物理恢复含义，
不得作为 control allocation qualification。

## 7. 输入失效与 fail-close

Runtime 正常路径先执行 `validate_flight_state()`，再调用 controller。Profile v1 必须区分：

- **state-validation layer**：dataclass 可以构造、但违反 `FlightState` 契约的对象应在调用
  controller 前被拒绝；
- **controller layer**：契约允许表达但不能安全产生普通命令的状态，以及非法 `dt`，必须
  返回 `FlightCommand.safe_stop()`。

覆盖要求如下：

| 条件 | 预期层级与结果 |
| --- | --- |
| `relative_pitch_rad=None` 且 IMU 标为 valid | state validation 拒绝完整测量矛盾，不调用 controller |
| `relative_pitch_rad=None` 且 IMU invalid/unobserved | 状态可合法表达；controller 返回 safe-stop |
| `relative_pitch_rad=NaN` | state validation 拒绝，不调用 controller |
| `relative_pitch_rad=+Inf/-Inf` | state validation 拒绝，不调用 controller |
| `imu.valid=false` | 合法构造时 controller 返回 safe-stop |
| `imu.fresh=false` | controller 返回 safe-stop |
| `required_inputs_fresh=false` | controller 返回 safe-stop |
| 必要 motor key 缺失 | state validation 拒绝，不调用 controller |
| motor 未观测，位置为 `None` | controller 返回 safe-stop |
| motor invalid/stale/unhealthy | 合法构造时 controller 返回 safe-stop |
| `dt=0`、负数、NaN、`+Inf/-Inf` | controller 返回 safe-stop |

所有 controller-layer safe-stop 都必须通过 `validate_flight_command()`，且不能抛出普通输入
处理异常或复用上一帧命令。

### 7.1 safe-stop 语义

`FlightCommand.safe_stop()`：

- 不等于 `/e_stop`；
- 不清除 ERROR/E-STOP；
- 不恢复 authority 或旧 owner；
- `motor_positions_rad=None`、`fan_commands=None`；
- 不能携带载荷或复用上一帧普通命令。

### 7.2 reset 语义

`reset()` 只清除算法内部状态。它不设置 IMU 或电机零点、不启用硬件、不获得 authority、
不清除 E-STOP/ERROR，也不改变 Runtime 状态。ALG-001 的 feedback law 本身应不依赖 pitch
历史；若 controller 为完整帧捕获本地电机基线，reset 后必须丢弃并从新场景重新捕获。

## 8. dt 边界

Runtime 标称约 50 Hz，但任何正有限 `dt` 都是合法输入，不能假设始终为 `0.02 s`。即使
ALG-001 的比例反馈暂不使用 `dt`，实现也必须对零、负、NaN 和正负 Inf fail-close。
ALG-001 不得使用 `dt` 提前实现 slew-rate、filter、damping 或其他时序能力。

## 9. Verification 与 Pass / Fail

ALG-001 使用 [Algorithm Benchmark v1](../ALGORITHM_BENCHMARK.md) 的 ALG-001 Profile v1：

- LEVEL A：必须覆盖纯算法/纯函数 feedback intent qualification；
- LEVEL B：必须覆盖 controller factory、状态/命令 validation、完整帧和 fail-close；
- LEVEL C：可作 synthetic DRY_RUN preview，但不替代 A/B，且本 Task Spec 建立时没有 candidate；
- LEVEL D–F：不属于 ALG-001 v1 qualification。

所有 Hard Qualification gate 必须 PASS，candidate 才能标为 `ALG-001 QUALIFIED`。独立比较
指标不能抵消任何安全失败。当前状态为 `NOT IMPLEMENTED`，因此不得记录 benchmark PASS。

## 10. Future-task boundary

ALG-001 禁止提前实现：

- **ALG-002**：角速度反馈、damping、motion trend；
- **ALG-003**：deadband、低通/噪声 filter、hysteresis、temporal smoothing；
- **ALG-004**：slew-rate limiting、output shaping、新动态 saturation strategy、执行器友好
  时序限制；
- **ALG-005**：`STABLE/DISTURBED/RECOVERING/SETTLING`、recovery timeout/phase logic；
- **ALG-006**：真实 motor/fan allocation、分配矩阵、actuator priority、最优组合；
- **ALG-007**：roll + pitch multi-axis recovery；
- **ALG-008**：完整扰动恢复或动态恢复性能结论。

必要输入检查、完整合法 `FlightCommand`、safe-stop、reset 和纯软件测试 seam 不属于越界。
若实现发现必须改变 Flight API、Runtime、authority 或硬件 manager/driver，应停止并拆分独立
API/architecture/safety review。

## 11. Out of scope

- 不实现或选择 ALG-001 candidate；
- 不调试真实机器人，不选择实际最优 `Kp`；
- 不标定 IMU/机械中位、电机方向、风扇推力或真实恢复方向；
- 不建立 actuator allocation；
- 不实现 filtering、damping、dynamic simulation 或 replay；
- 不进行硬件测试，不访问 IMU/CAN/串口/GPIO/PWM/ESC/电机/风扇；
- 不发布 v0.5.0。

本 Task Spec 的通过范围仅限固定 synthetic software fixtures 上的基础姿态反馈语义和现有
Flight contract。它不能扩展为可恢复倾角、安全倾角或真实 Balance Recovery 结论。
