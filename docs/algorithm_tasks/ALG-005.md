## 2. 单一目标与能力链路

ALG-005 唯一新增主要能力是 **Recovery Process / 恢复过程管理**：观察合法的单轴 pitch、
pitch-rate、继承历史与合法 `dt`，建立可测试的 recovery episode，管理恢复、settling、稳定
确认和 timeout，并输出最终 abstract recovery intent 与 task-local 过程观测。

```text
FlightState
  -> ALG-001 attitude feedback
  -> ALG-002 damping
  -> ALG-003 input noise robustness
  -> ALG-004 output shaping
  -> ALG-005 recovery process
  -> final abstract recovery intent
```

phase、episode timer 和 dwell timer 是 qualification 所需的 task-local observable seam；不要求
production Candidate 使用特定 FSM、枚举或类，也不修改公开 `FlightController`、`FlightState`
或 `FlightCommand`。如果最终 process intent 不等于 inherited ALG-004 shaped intent，它仍必须
重新通过 ALG-004 的幅值、slew、directed-transition、reset 和继承 Hard Gates。
TIMED_OUT 的精确零输出是继承 fail-close 的 stop sentinel，不是 ordinary shaped output；
该边界按 safe-stop 评分，不把 sentinel 跳变计作 ordinary slew。timeout 前及 reset 后所有
ordinary process intent 均完整受 ALG-004 gate 约束，不能为普通过程管理增加豁免。

## 3. 输入、阈值与比较语义

只允许使用统一的 `relative_pitch_rad`、`relative_pitch_rate_rad_s`、当前正有限 `dt` 和继承的
task-local history。不得重新解释 raw gyro、坐标或符号，不得使用 wall clock 或测试机器执行
时间。Profile v1 冻结：

```text
disturbance trigger:
  abs(pitch) >= 0.040 rad OR abs(pitch_rate) >= 0.200 rad/s

settling envelope:
  abs(pitch) <= 0.020 rad AND abs(pitch_rate) <= 0.100 rad/s

stable confirmation envelope:
  abs(pitch) <= 0.010 rad AND abs(pitch_rate) <= 0.050 rad/s

stable dwell = 0.300 s continuous valid time
recovery timeout = 3.000 s valid episode time
```

`>=` 和 `<=` 均包含边界。timer 只累计 controller 已接受的正有限 `dt`；invalid/stale/unhealthy
输入、validation reject、非法 `dt`、wall-clock delay 和测试执行时间均不能累计。阈值只是
`ALG-005 Profile v1` synthetic software qualification envelope，不是机器人安全倾角、最大可恢复
倾角、真实 IMU noise envelope、执行器 capability 或 hardware safety envelope。

## 4. 可观察 phase 与 episode 语义

必须可观察 `STABLE`、`DISTURBED`、`RECOVERING`、`SETTLING`、`TIMED_OUT`：

- **STABLE**：没有 active episode。cold start 的稳定输入处于 STABLE；未触发 disturbance 的
  guard-band 输入不虚构 episode。active episode 只有连续满足 stable confirmation envelope
  `0.300 s` 后才回到 STABLE，单帧过零不能提前结束。
- **DISTURBED**：无 active episode 时首次满足任一 disturbance trigger 的 episode 起点；该
  update 必须显式可观察，不能静默跳过。episode elapsed 从此边界开始。
- **RECOVERING**：episode active、尚未处于 settling envelope、且未 timeout；recovery timer
  连续累计合法 `dt`。
- **SETTLING**：episode active 且当前处于 settling envelope，但尚未完成 stable dwell。离开
  settling envelope 回到 RECOVERING；只离开更严格的 stable confirmation envelope 时清零
  stable dwell、仍保持 SETTLING。任何 setback 都不得重置 episode timer。
- **TIMED_OUT**：episode 的有效累计时间达到 `3.000 s` 前仍未重新确认 STABLE。timeout 可观察、
  latch，Level A/D/E 最终 process intent 为精确 `0.0`，Level B 返回现有精确
  `FlightCommand.safe_stop()`；普通合法输入不得自行解除，只有显式 `reset()` 可清除。

已有 timeout latch 与外部 validation/fail-close 优先。普通合法 update 先检测无 episode 的
disturbance entry，再累计当前 `dt`；active timeout 优先，只有 episode elapsed 仍小于 timeout
时才可由完整 stable dwell 进入 STABLE；否则按 active SETTLING/RECOVERING 或 inactive STABLE
显示，首次触发 update 必须保留 DISTURBED 观测。
完整的离散 timer 记账与 timeout 窗口由 Profile v1 冻结。

## 5. Reset、fail-close 与 history

显式 `reset()` 原子清除 ALG-001～003 输入/filter history、ALG-004 shaped-output history、
ALG-005 phase/history、episode/settling timer、stable dwell、timeout latch 和 task-local cache/counter；
reset 后同一合法输入必须等价于 fresh cold start。reset 不修改 Runtime、authority、ownership、
IMU zero、E-STOP、ERROR 或硬件状态。

外部 controller-layer invalid/stale/unhealthy/`required_inputs_fresh=false`/非法 `dt` 继续精确返回
`FlightCommand.safe_stop()`，不复用旧 ordinary command 或 recovery intent，并清除 ALG-001～005
全部 task-local history；下一合法输入等价于 fresh cold start。state-validation reject 仍是前置
拒绝，由 harness 显式 reset 后检查恢复，不得记成 controller-layer safe-stop。

ALG-005 自身 `TIMED_OUT` 是内部 process failure，不作为 transient external fault 自动清除；
timeout latch 保持到显式 reset。它不改变 Runtime authority、E-STOP 或真实硬件状态。
外部 fail-close 的 cold-start 恢复规则适用于未锁存 timeout 的路径；已锁存后，transient
fault 仍 safe-stop 且不得累计 timer/复用 ordinary history，但不能间接清除 timeout latch。
validation reject 仍是前置拒绝，只有 harness 显式 reset 可以清除 latch。

## 6. Verification levels 与冻结资产

- **Level A — HARD GATE**：直接评分 final abstract process intent、phase、timer、reset 和继承；
- **Level B — HARD GATE**：factory、state/command validation、完整当前 hold frame、fan-zero 和
  精确 safe-stop；不从执行器 payload 反推 intent；
- **Level C — optional preview**：不能替代 A/B/D/E；
- **Level D — HARD GATE**：`ALG005-FIXTURE-v1` 的 deterministic scripted process replay，覆盖
  neutral、正负扰动、正常恢复、settling setback、timeout、reset、fail-close、非法 `dt`、顺序、
  mirror 和 repeatability；不是 dynamic simulation；
- **Level E — HARD GATE**：`ALG005-SYNTHETIC-PLANT-v1` 的 deterministic normalized single-axis
  closed-loop benchmark，覆盖 E00、E01P/N、E02P/N、E03P/N、E04P/N、E90P/N；不是可信物理
  机器人模型、sim-to-real evidence 或硬件验证；
- **Level F — NOT AUTHORIZED / NOT EXECUTED**。

Level D 直接评分过程状态语义，Level E 直接评分冻结模型内的闭环 recovery；任一层失败都不能
由另一层或 comparative metrics 抵消。完整模型、更新顺序、场景与 Hard Gates 仅以 Profile v1
为准，Task Spec 不另建不同数字版本。

仍是当前 inherited requested intent 的 clamp，不能改成新 process target 来规避约束。
timeout stop sentinel 单独按 fail-close 评分，不为任何普通输出提供豁免。

普通 Level B 命令仍只复制当前合法完整 motor feedback position hold，左右 fan 为 `0.0`；
TIMED_OUT 与外部 fail-close 使用无载荷 `FlightCommand.safe_stop()`。不得把 abstract intent 编码
成 motor、fan、PWM、torque 或 position。Runtime、authority、ownership、watchdog、lease、
soft limits、E-STOP、安全退出和底层最终否决权保持不变。
