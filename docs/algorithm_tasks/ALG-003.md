# ALG-003 — Noise Robustness / 噪声鲁棒性

本文是 ALG-003 的独立 Task Spec。它在 ALG-001 基础姿态反馈和 ALG-002 运动趋势/阻尼之上，
增加针对小幅 synthetic 输入波动的噪声鲁棒性。本文不是候选实现、真实 IMU 噪声模型、输出
整形、动态仿真、硬件操作手册或硬件授权。共享接口以
[Flight Control API](../FLIGHT_CONTROL_API.md) 为准，固定序列、指标和阈值见
[Algorithm Benchmark v1 / ALG-003 Profile v1](../ALGORITHM_BENCHMARK.md#10-alg-003-profile-v1)。

## 2. Objective

ALG-003 唯一新增的主要能力是：降低小幅 IMU 波动、量化噪声和轻微扰动在软件输入中造成的
持续无意义输出、高频小幅抖动、频繁正负反向和无效控制动作，同时保留对真实、有意义的姿态
误差与运动趋势的及时响应。

资格判断必须同时通过两个互不抵消的 Hard Gate：

1. **Noise Suppression Gate**：固定小噪声序列上的输出活动、总变化、峰值和有效符号反转受到
   Profile v1 的量化约束；
2. **Signal Preservation Gate**：明显超出 noise envelope 的正负姿态与 pitch-rate 变化仍在
   有限帧数内产生正确、有意义且持续的响应，并保留 ALG-002 的 diverging/recovering 区分。

任一 gate FAIL 都得到 `ALG-003 NOT QUALIFIED`。输出恒为零、长期停留在 deadband、无限延迟
或只追求曲线平滑的 candidate 必然不能通过 Signal Preservation Gate。

## 3. 正式输入与责任边界

### 3.1 控制输入

控制律只允许消费统一的软件状态：

- `state.imu.relative_pitch_rad`，单位 rad；
- `state.imu.relative_pitch_rate_rad_s`，单位 rad/s；
- `dt`：相邻控制器周期之间的本地单调时钟时间差，单位秒。算法必须把它作为可变的正有限
  值处理，不能把它当作 absolute timestamp，也不得自行读取 ROS clock 或 hardware clock。

`relative_pitch_rate_rad_s` 与 `relative_pitch_rad` 使用同一软件 pitch 正方向。candidate 不得
直接读取 `angular_velocity_rad_s` 的 raw gyro XYZ，不得自行选择 gyro 轴或重新解释符号，
也不得用 pitch 历史有限差分替代公开 rate。

### 3.2 安全检查与合法命令输入

candidate 可以读取 `imu.valid/fresh`、`system.required_inputs_fresh`、E-STOP 摘要、必要 motor
feedback 和构造合法完整 `FlightCommand` 所需的状态，但这些字段只用于 fail-close、保持当前
合法 motor frame 或形成 fan-zero 预览，不构成新控制能力。`required_inputs_fresh=true` 不是
整个系统或硬件已就绪的声明。

## 4. Fixture 与结论边界

`ALG003-FIXTURE-v1` 是显式列值、无运行时随机数的 **synthetic software noise fixture**。
它的 pitch noise 不超过 `±0.004 rad`，pitch-rate noise 不超过 `±0.04 rad/s`；有意义的信号
使用 `±0.05 rad` 与 `±0.20 rad/s`。这些数值简单、对称、可重复，并与 ALG-001/ALG-002 的
正常场景明显区分。

这些幅值不是 Hiwonder IMU 实测分布、真实量化误差、机器人振动谱、传感器 noise envelope、
安全姿态/角速度或可恢复范围。当前没有受控真实 IMU 噪声采集；Profile v1 只建立纯软件的
关系型资格。未来真实 IMU characterization 必须作为独立、受授权的工作单元，不能静默改变
本 fixture。

Profile v1 冻结四类 noise sequence、正负 meaningful step、diverging/recovering trend、
`dt` variants、fail-close 和 reset/history 场景。完整列值与稳定 scenario ID 见 Benchmark。

## 5. Raw inherited baseline

噪声抑制必须相对于同一输入序列的 `raw inherited baseline` 评分，不能只观察 candidate 自身。
Profile v1 将继承参考关系冻结为：

```text
raw_intent(pitch, rate) = -1.0 * pitch - 0.1 * rate
```

单位分别对应 `Kp=1.0 intent/rad` 与 `Kd=0.1 intent/(rad/s)`。该公式冻结的是 ALG-001/002
已资格化的软件继承语义与 Profile 参考配置，不要求导入、调用或复制当前 ALG-002 production
module，也不锁定 ALG-003 candidate 的具体抑噪结构。所有 candidate 都对同一显式公式和序列
比较；不得通过改变 raw baseline、逐场景调参或事后选择窗口取得优势。

## 6. Expected behavior

### 6.1 Noise suppression

平衡附近 pitch/rate 小幅交替时，candidate 必须相对 raw baseline 降低输出总变化量、平均绝对
活动和峰值，并把超出零容差的有效正负反转限制在固定上限。非零稳定姿态附近叠加小噪声时，
仍须降低总变化量，且正负镜像序列得到镜像响应。

Profile 不要求输出完全为零，也不规定必须使用 deadband、low-pass、moving average、median、
hysteresis 或任何其它特定方法。可解释且满足相同 gate 的方案均可成为 candidate。

### 6.2 Meaningful signal preservation

从平衡附近噪声进入明显的正/负 pitch + rate disturbance 后，candidate 必须：

- 保持与 inherited raw intent 一致的正确方向；
- 在 Profile 的有限最大帧延迟内达到有效响应阈值；
- 在持续输入的末端窗口保留规定比例的稳态响应，不能永久衰减到零；
- 对正负场景保持镜像一致性。

延迟以 sequence frame 数和对应 synthetic elapsed time 同时记录，不推导真实机器人时间 SLA。

### 6.3 Trend preservation

相同非零 pitch 下，从 zero-rate 进入 diverging 或 recovering rate 后，输出必须沿 ALG-002
定义的反 rate 方向产生足够 separation。recovering total intent 仍允许穿过零点；不能因加入
filter、deadband 或 latch 而重新定义 ALG-002 语义。pitch-rate 不能被忽略。

## 7. ALG-001 / ALG-002 inheritance

未来 ALG-003 candidate 必须在无噪、标准确定性输入下重新运行未修改的继承资格：

- ALG-001：neutral、direction、proportional-style consistency、magnitude monotonicity、
  symmetry、finite output、repeatability、fail-close、reset、factory 和 Level B validation；
- ALG-002：zero-rate、diverging、recovering、zero-pitch moving、signed damping separation、
  mirror consistency、finite output、repeatability、fail-close、`dt`、reset、factory 和 Level B
  validation。

该 gate 不修改 ALG-001/ALG-002 Task Spec、Profile 或历史 Candidate Result，也不允许以历史
PASS 代替当前 ALG-003 candidate 的回归结果。

## 8. `dt` contract

- `dt` 必须是正、有限的秒数；不得假设固定为 `0.02`；
- Profile 至少以常量 `0.020 s`、常量 `0.037 s` 和二者交替的序列验证历史行为；
- 若 candidate 使用时间常数，配置应以秒为单位；固定帧设计只有在说明其对所有 `dt` variants
  的语义并通过同一 gate 时才可接受；
- history/filter 更新必须使用当前合法 `dt`，不得读取 ROS 或硬件时钟；
- `0`、负数、NaN、`+Inf/-Inf` 必须 fail-close，并使本地历史失效；
- Profile 的 frames-to-response 同时报告累计 synthetic elapsed time，不代表真实响应时间。

## 9. Invalid、stale、missing 与恢复

Runtime 正常路径先 `validate_flight_state()`，再调用 controller。Profile 必须区分：

- state-validation layer：valid IMU 的 pitch/rate 为 `None`，或 pitch/rate 为 NaN/Inf 等契约
  矛盾由 validation 拒绝，不调用 controller；
- controller layer：合法 unobserved/invalid IMU、IMU stale、
  `required_inputs_fresh=false`、必要 motor 不可用、E-STOP 不明确为 false，以及非法 `dt`，
  返回精确的 `FlightCommand.safe_stop()`。

任何 controller-layer fail-close 都必须清除 filter history、hysteresis/deadband latch、缓存
观测和上一 command。下一合法样本按 cold start 重建，结果必须等价于 `reset()` 后输入同一
样本；不得把旧 filtered state 冒充新鲜观测。前置 validation 拒绝由测试 harness 调用
`reset()` 后再检查恢复，以模拟 Runtime 不把非法状态交给 controller 的边界。

## 10. Reset 与 history isolation

稳定场景 `ALG003-R01` 要求 `reset()`：

- 清除全部 filter/history、hysteresis/deadband latch、candidate-local baseline 与命令缓存；
- 不复用上一 sequence 的状态或上一普通 command；
- reset 后相同输入序列必须与全新 controller 的 cold run 等价；
- 不修改 Runtime，不设置 IMU zero，不清除 E-STOP/ERROR，不取得 authority，不访问硬件。

`ALG003-R02` 还以正负镜像 sequence 的不同执行顺序验证场景隔离；交换顺序不得改变各自结果。

## 11. FlightCommand 与安全边界

Level A 观察 task-local `pitch_feedback_intent` sequence。Level B 通过现有 factory/loader 调用
controller，并验证每一帧：普通命令包含完整且有限的 motor frame 与合法 fan command；
fail-close 精确返回不含载荷的 safe-stop。Profile 不从 motor/fan payload 反推 intent，不评分
真实 actuator direction，也不允许算法接触 ROS 或硬件 I/O。

Runtime、authority、E-STOP、watchdog、lease、软限位、停用与安全退出保持最终裁决权。

## 12. Verification 与 Pass / Fail

ALG-003 使用 Algorithm Benchmark v1 / ALG-003 Profile v1：

- Level A：提供无 ROS、无硬件的 task-local 纯软件算法观测 seam，观察抽象控制量并验证算法
  计算本身；
- Level B：独立验证 factory、`FlightState`、`FlightCommand` validation、完整 frame、safe-stop 与
  历史失效；
- Level D：使用 `ALG003-FIXTURE-v1` 冻结的 Q/S sequence 按顺序驱动同一个 Level A seam，
  组织和评分 history、noise suppression、response delay、trend preservation、reset/replay 与
  repeatability；它是 deterministic software replay / benchmark orchestration，不要求新的 production
  API，也不是 dynamic/closed-loop simulation、Runtime integration、actuator simulation 或 hardware
  replay；
- Level C/E/F：不属于 ALG-003 v1 Hard Qualification。

ALG-003 v1 Hard Qualification 包含 Level A、Level B 和 Level D；三个层级职责不能互相替代。

Noise Suppression 与 Signal Preservation 必须分别 PASS，且全部全局/任务 Hard Gate PASS 后
才能写 `ALG-003 QUALIFIED`。任一失败都写 `ALG-003 NOT QUALIFIED`；comparative metrics
不能抵消失败。当前 implementation 为 `NOT IMPLEMENTED`，不得创建虚构 Candidate Result。

## 13. Future-task boundary

ALG-003 不得提前实现：

- **ALG-004**：对最终 intent 的 saturation、slew-rate limiting、output shaping 或输出变化
  速度限制；输入估计/抑噪不能用最终输出 rate limiter 冒充；
- **ALG-005**：`STABLE/DISTURBED/RECOVERING/SETTLING`、recovery state、timeout 或过程管理；
- **ALG-006**：motor/fan allocation、allocation matrix、actuator priority 或真实方向映射；
- **ALG-007**：roll 或 multi-axis recovery；
- **ALG-008**：完整 disturbance recovery 或真实动态恢复结论。

同时禁止 integral/windup、raw gyro axis/sign logic 和硬件参数标定。必要输入检查、明确的本地
history、safe-stop、完整合法 `FlightCommand` 和无硬件测试 seam 不属于越界。

## 14. Out of scope

- 不创建或实现 ALG-003 Candidate A/B，不选择最优抑噪方法或真实调参；
- 不修改 ALG-001/ALG-002 implementation、Task Spec、Profile 或历史 Result；
- 不改变 Flight API、Runtime、adapter、default controller、hardware config 或执行器映射；
- 不建立真实 IMU 噪声模型、动态模型、可信闭环仿真或真实 Balance Recovery；
- 不访问 IMU/CAN/串口/GPIO/PWM/ESC/电机/风扇；
- 不发布 v0.5.0。

本 Task Spec 的结论仅限 `ALG003-FIXTURE-v1` 的 synthetic software qualification。它不能用来
声称真实 IMU 已表征、真实机器人不会振荡、电机不会抖动或 Balance Recovery 已实现。
