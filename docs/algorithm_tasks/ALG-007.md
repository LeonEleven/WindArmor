## 2. 已审计的软件事实和非目标

| 问题 | 当前证据与设计结论 |
| --- | --- |
| 输入/输出能否表示双轴 | `FlightState.imu` 有 `relative_pitch_rad`、`relative_roll_rad`；只有统一的 `relative_pitch_rate_rad_s`，没有公开的相对 roll rate。`FlightCommand` 是完整 absolute motor rad 目标与左右 `[0,1]` fan 命令，没有抽象双轴 intent 字段。 |
| Controller 是什么接口 | `FlightController.update(state, dt)` 不规定轴数；ALG-001～006 当前实现和 task-local seam 均只处理 pitch，因此实现是单轴，接口本身隐式允许多轴读取。工厂是 `module.path:factory`。 |
| 当前饱和语义 | ALG-004 限制**单个** abstract intent 的 `abs(u)<=0.10` 与相邻 ordinary 帧 `abs(Delta u)<=2.0*dt`；ALG-006 以 common-`q` 对单轴 normalized request 和三个 synthetic resource 取最小值并保存 signed residual。`FlightCommand` validation 逐载荷校验；底层电机软限位、步长/速度及 fan ramp 是独立最终约束。当前没有双轴 vector envelope。 |
| 可验证的软件分配 | ALG-006 仅有单轴 normalized synthetic allocation；没有 pitch/roll 物理矩阵、roll actuator projection 或验证过的多轴 arbitration。 |
| availability | `valid/fresh/healthy`、`output_known`、`actuation_allowed` 和 owner/readback 是状态/裁决；不存在 runtime availability → numerical authority 的已验证映射。 |
| hardware metadata | `left/right_lift` 与 `left/right_pitch` 是逻辑键；CAN ID、`motor_signs`、软限位、GPIO12/26、PWM 范围描述连接与保护，不证明恢复力矩/推力。 |

## 3. Preconditions、inputs / outputs 与软件契约

未来 Candidate 仍须通过现有 factory 创建纯 Python `FlightController`，实现 `reset()` 与
`update(FlightState, positive finite dt)`。Runtime 的 state/command validation 保持前置/后置；
算法不读取 ROS/硬件，也不自行获得 authority。普通 Level B 输出仍是完整当前 motor feedback
position hold、左右 fan `0.0`；任何需要恢复动作的非零 absolute rad/PWM projection，须先另立
经过 review 的契约，不能由 task-local intent 猜测。

Level A/D 的 **task-local、software-only** 联合观测至少包含同一帧的
`(pitch_request, roll_request)`、`(pitch_served, roll_served)`、signed residual vector、
`status/disposition` 与继承的 process phase/timeout latch。请求和服务量是无量纲 normalized
软件量，不是 `FlightState`/`FlightCommand` 字段或真实 torque/thrust。合法普通请求各分量位于
`[-1,1]`；pitch 归一化仅沿用 ALG-006 的 `u_pitch/0.10`，roll 的 request 来源、角速度/趋势
语义及与 `0.10` 的关系 **待 review 冻结**，不得直接套用 pitch gain。每帧同步读取两轴，
不得把同一时刻的组合扰动拆成两个相互独立运行的单轴资格结果。

所有普通输出必须 finite、可重复、有界；每轴服务方向不得与该轴合法非零 request 相反，
零请求不能获得虚构的该轴服务量；`residual_i=request_i-served_i` 保留符号。饱和不能绕过
ALG-004 ordinary pitch envelope/slew 或任何 Level B/底层限制。ALG-005 `TIMED_OUT` 的零是
stop sentinel，优先于普通双轴零；精确 safe-stop 且 latch 只能由显式 reset 解除。

## 5. Multi-axis、耦合、饱和与 arbitration 要求

联合场景须同时改变 pitch/roll，记录逐帧双轴 request、served、residual 与 phase；至少覆盖
同号、反号、大小不等、一个轴先达到限幅及一个轴为零的情况。单轴回归必须保留 ALG-001～006
pitch 语义；roll-only 场景必须有明确 roll 软件方向与中性响应，但**roll 角速度坐标和动态
阻尼仍未定义**，不能声称继承了 pitch 的 rate 证据。

资格 fixture 可以定义两个独立轴上限与一个共享的 **synthetic normalized budget**。合法
served vector 必须满足每轴请求/上限及联合预算，residual 显式记录；一轴达到上限但另一轴
仍有软件预算时，不能无理由把另一轴置零。共享预算只是制造竞争的测试约束，不代表电机
或风扇真实 authority。其具体数值、测试向量与期望关系见 planned profile；任何变化须版本化。

必须有 explicit arbitration contract：输入合法性、timeout/fault、限幅、deterministic 决策、
残差和不复用旧帧的顺序固定；相同输入与相同 reset/history 产生相同结果，场景执行顺序
不改变结果。**pitch-first、roll-first、等比分配和硬件权重均无当前证据支持，不在此指定。**
Candidate 必须在实现前提交可测试的优先级/竞争规则，并经独立 review 冻结 Profile 的确切
关系；未经该决定，combined-saturation 的 Formal Qualification 不可执行。

轴耦合只允许 `synthetic / normalized / software stress model`。fixture 应把同一输出向量注入
两个软件状态分量，检验竞争下两个轴不会被彼此遗漏，并记录逐轴状态/趋势和残差；耦合
系数、更新顺序、初态、扰动及 score 必须在 Candidate 实现前固定。当前仓库无经过验证的
物理 coupling matrix，故不得把该 fixture 称为 WindArmor 真实动力学。

## 6. Fail-close 与 qualification design

前置 state validation 拒绝 NaN/Inf 或缺失的有效 IMU 分量；controller-layer 的 stale、unknown、
unhealthy、E-STOP 非明确 false、非法 `dt`、roll source 不可用、contract/internal failure 必须
返回 exact `FlightCommand.safe_stop()`，清除 ordinary 双轴历史及 allocation，不借另一轴继续
输出。已 latch 的 timeout 保留至显式 reset。普通双轴零是合法 neutral；timeout zero、fault
zero 和已知 synthetic zero-capability 的 infeasible 诊断不能混淆。故障恢复后的第一普通帧与
fresh cold run 等价；Level B 不从 `actuation_allowed`、motor/fan health 推导数字 authority。

规划中的 Level A/B/D 覆盖双轴静态关系、同步 sequence、耦合压力、共享饱和、reset 和故障；
ALG-001～006 inheritance 原样重跑，ALG-005 Level E 仍仅证明单轴 synthetic pitch。新的多轴
Level E 必须在 roll rate/source、synthetic coupling plant 和中立的恢复阈值完成 review 后再冻结；
**不能用两项单轴 PASS 或只有 A/B/D 的 PASS 代替 M3 多轴动态 qualification**。已存在的软件
容差 `abs_tol=1e-9`、`rel_tol=1e-6` 可用于派生数值比较；exact sentinel、enum、场景计数、
合法边界和 reset 不用 tolerance。ALG-005 的 `dt=0.020 s`、`0.300 s` dwell、`3.000 s` timeout
及 pitch Level E 门槛只在原单轴 fixture 继承，不自动扩展为 roll 的物理或双轴恢复阈值。

正式资格前必须冻结 Profile v1 的 roll 信号来源、arbitration、coupling 参数、场景样本数/
horizon、双轴 recovery/settling/overshoot/oscillation gate；针对固定 implementation commit
fresh 运行全部 Hard Gates 与 Software CI，再单独创建 Candidate Result。当前**没有** ALG-007
Formal Qualification PASS。

## 7. Hardware evidence boundary 与未验证声明

软件 contract 仅证实 API 字段、校验、安全分层与 ALG-001～006 的已记录软件资格；planned
vector budget/coupling 是 synthetic benchmark assumption。以下保持 **UNKNOWN / NOT VERIFIED**：
motor torque effectiveness、fan RPM/thrust/direction/moment arm、pitch/roll physical allocation
matrix、motor/fan relative/dynamic authority、runtime availability → numerical authority、真实
cross-coupling、safe recovery envelope、maximum recoverable disturbance、real closed-loop
stability、sim-to-real、real actuator safety 与 real Balance Recovery。available 只代表状态，
绝不自动表示该 actuator 对某轴的数值 authority。硬件 metadata 不填补这些空白。

## 8. Open design questions / review items

   有明确采样、wrap、validity 和冷启动规则的纯软件估计？当前 raw body rate 不能直接充当

3. **Qualification review：** synthetic coupling 系数、动态 Level E 模型与 roll/双轴阈值、
   horizon、sample count 如何预先冻结？证据不足时标为 TBD，不得声称 QUALIFIED。
4. **Hardware-dependent unknown：** 非零 FlightCommand projection、真实轴向力矩/推力与
   runtime availability-to-authority mapping 需未来独立 characterization/review；不属于本任务。
