# ALG-002 — Motion Trend / Damping / 运动趋势与阻尼

本文是 ALG-002 的独立 Task Spec。它在 ALG-001 基础姿态反馈之上增加瞬时 pitch 运动趋势与
阻尼的软件能力，不是候选实现、动态仿真、执行器分配、硬件操作手册或硬件授权。共享接口
以 [Flight Control API](../FLIGHT_CONTROL_API.md) 为准，统一资格规则和固定场景见
[Algorithm Benchmark v1 / ALG-002 Profile v1](../ALGORITHM_BENCHMARK.md#9-alg-002-profile-v1)。

## 2. Objective

在 ALG-001 已验证的基础姿态反馈之外，使用与相对 pitch 采用同一软件正方向的瞬时
`relative_pitch_rate_rad_s`，使控制器能够区分：

1. 已经倾斜且仍在继续远离平衡位置；
2. 已经倾斜但正在向平衡位置恢复；
3. 当前位于平衡位置附近但仍具有明确运动趋势。

ALG-002 只证明固定 synthetic software fixture 中的 motion-trend/damping 关系、继承能力和
失效后安全闭锁。它不证明机器人动力学、真实恢复力矩、恢复时间、overshoot、可恢复倾角、
真实 Balance Recovery 或任何执行器方向。

## 3. 正式输入与责任边界

### 3.1 控制律输入

ALG-002 控制律允许使用且只新增使用：

- `state.imu.relative_pitch_rad`：相对当前 IMU zero reference 的软件 pitch，单位 rad；
- `state.imu.relative_pitch_rate_rad_s`：上述 pitch 的瞬时变化率，单位 rad/s。

正式符号为：

```text
relative_pitch_rate_rad_s > 0  -> relative_pitch_rad 正在增加
relative_pitch_rate_rad_s < 0  -> relative_pitch_rad 正在减小
relative_pitch_rate_rad_s = 0  -> 当前瞬时 pitch 变化率为零
```

ALG-002 不直接使用 `state.imu.angular_velocity_rad_s` 作为 pitch-rate 控制输入，也不在
controller 中实现 raw gyro 轴选择、坐标变换或 `pitch_axis_sign`。这些责任已经属于 Flight
adapter。controller 不得通过 pitch 历史和 `dt` 再做有限差分来替代公开 rate。

### 3.2 安全检查与合法命令输入

实现可以读取 ALG-001 已允许的安全状态、必要 motor feedback 和 `dt`，但这些字段只用于
fail-close、保持非控制轴或形成完整合法命令，不构成新的控制能力。实现必须先尊重
`validate_flight_state()` 的 state-validation layer，再在 controller layer 对契约允许但不宜
产生普通命令的状态返回 `FlightCommand.safe_stop()`。

## 4. 误差、抽象意图与运动趋势

继承 ALG-001 的目标和误差定义：

```text
target_pitch_rad = 0.0
pitch_error_rad = target_pitch_rad - relative_pitch_rad
```

`pitch_feedback_intent` 继续使用无量纲 software intent unit。基础恢复方向与
`pitch_error_rad` 同号；新增 damping 分量应反对当前 `relative_pitch_rate_rad_s`。该定义只
用于 task-local 纯软件 seam，不新增 Flight API 字段，也不表示真实 actuator direction。

令：

```text
pitch = relative_pitch_rad
rate = relative_pitch_rate_rad_s
```

- `pitch * rate > 0`：`abs(pitch)` 正在增加，定义为 **diverging / 继续远离平衡**；
- `pitch * rate < 0`：`abs(pitch)` 正在减小，定义为 **recovering / 正在恢复**；
- `rate = 0`：定义为 **zero-rate / 瞬时静止趋势**。

实现和 benchmark 使用 Profile v1 的软件容差判断零值与关系，不把浮点完全相等作为所有
资格判定方式。

## 5. Expected behavior

### 5.1 Zero-rate behavior

当 `rate=0` 时，ALG-002 必须保持 ALG-001 的 neutral、direction、proportional-style
attitude feedback、magnitude monotonicity、symmetry、repeatability、safe-stop 和完整
`FlightCommand` 语义。它不要求复制 Candidate A 的内部结构，但必须通过 ALG-001
inheritance gate。

为比较相同 pitch 下 rate 对 feedback 的有符号影响，Profile v1 定义：

```text
P00 = intent(+pitch, 0)       P01 = intent(+pitch, +rate)  P02 = intent(+pitch, -rate)
N00 = intent(-pitch, 0)       N01 = intent(-pitch, -rate)  N02 = intent(-pitch, +rate)
```

其中 `P01/N01` 是 diverging，`P02/N02` 是 recovering。`P00` 保持 ALG-001 的负反馈，
`N00` 保持 ALG-001 的正反馈。

### 5.2 Diverging behavior

对同一非零 pitch，若 `pitch * rate > 0`，非零 rate 必须使 total feedback 相对于同 pitch
的 zero-rate baseline 沿反对 rate 的方向发生可观察变化。在 Profile v1 的固定 envelope 内：

```text
positive pitch + positive rate:  P01 < P00, 且 P00 - P01 > tolerance
negative pitch + negative rate:  N01 > N00, 且 N01 - N00 > tolerance
```

### 5.3 Recovering behavior

对同一非零 pitch，若 `pitch * rate < 0`，damping 仍应反对当前 rate，而不是要求 total
feedback 始终指向 `pitch=0`。在 Profile v1 的固定 envelope 内：

```text
positive pitch + negative rate:  P02 > P00, 且 P02 - P00 > tolerance
negative pitch + positive rate:  N02 < N00, 且 N00 - N02 > tolerance
```

因此 `P02` 可以为负、在零容差内为零或为正，`N02` 可以为正、在零容差内为零或为负；
recovering total intent 在穿过 pitch 零点前反号本身不是资格 FAIL。它可以表示 damping 正在
制动朝零点的运动以减少未来 overshoot。该判断只证明软件 feedback intent 中 rate 作用的
方向，不证明真实机器人会减少 overshoot。

### 5.4 Zero-pitch moving behavior

当 `pitch=0` 且 `rate!=0` 时，姿态误差为零但仍在经过目标姿态。反馈必须反对当前 rate：

```text
rate > 0  -> pitch_feedback_intent < 0
rate < 0  -> pitch_feedback_intent > 0
```

两个非零 intent 都必须严格超过 Profile 的 direction 零容差。这是 ALG-002 相比 ALG-001 的
关键新增软件能力之一。它与 recovering 判定采用同一原则：damping contribution 始终反对
当前 `relative_pitch_rate_rad_s`，而不是要求 total intent 始终指向 `pitch=0`。

### 5.5 Damping effect present

Profile v1 要求 `P01/P02/N01/N02` 四个正常非零 rate 场景相对于各自同 pitch 的 zero-rate
baseline，均沿反对 rate 的方向变化，并且每个有符号差值都严格超过 damping-effect
tolerance。不能只让每个正负 pitch 组中的一个场景体现 rate 作用；同时还必须通过镜像
一致性和 zero-pitch moving gate。否则结果为 `ALG-002 NOT QUALIFIED`。

### 5.6 不锁定具体控制律

Task Spec 不强制候选使用 `Kp * error - Kd * rate`。PD 风格或其它可解释的瞬时 damping
设计均可，但必须满足固定 Profile 的全部关系和安全 gate。具体 `Kd`、其它参数及其合法范围
属于未来 candidate implementation decision；参数越大不表示越好。

## 7. FlightCommand 与执行器边界

与 ALG-001 一致：

1. Level A 从 task-local seam 观察 `pitch_feedback_intent`；
2. Level B 只验证 factory、state/command validation、完整 motor frame、合法 fan command
   和 safe-stop；
3. 不从 motor/fan payload 反推软件 intent，不对真实电机或风扇方向评分。

`relative_pitch_rad`、`relative_pitch_rate_rad_s` 和 `pitch_feedback_intent` 的正负均不能
推导真实电机位置增减、旋转方向、左右风扇增减、恢复力矩或推力方向。真实 actuator
coordination 留给 ALG-006。

## 8. 输入失效与 fail-close

### 8.1 State-validation layer

以下对象违反当前 `FlightState` 契约，应由 `validate_flight_state()` 在 controller 调用前
拒绝：

- valid IMU 的 `relative_pitch_rate_rad_s=None`；
- `relative_pitch_rate_rad_s=NaN/+Inf/-Inf`；
- 其它由 ALG-001 已定义的非有限、缺失或交叉字段矛盾。

前置拒绝是对应 validation-layer 场景的 PASS；不得绕过 validation 强行调用 controller，
也不得把“controller 未运行”记成 controller-layer PASS。

### 8.2 Controller layer

以下可合法表达但不能产生普通命令的状态必须返回精确、无载荷且通过
`validate_flight_command()` 的 `FlightCommand.safe_stop()`：

- 合法 unobserved/invalid IMU；
- `imu.fresh=false`；
- `required_inputs_fresh=false`；
- 必要 motor feedback unobserved/invalid/stale/unhealthy；
- E-STOP 未知或不是明确 false；
- 非法 `dt`。

所有 ALG-001 safety contract 继续适用。safe-stop 不等于 `/e_stop`，不清除 ERROR/E-STOP，
不恢复 authority/owner，也不复用上一普通 command。

## 9. `dt`、状态与 reset

任何正有限秒数都是合法 `dt`，不得假设固定 `0.02 s`。由于 ALG-002 直接消费公开的瞬时
pitch rate，同一 `pitch + rate + configuration` 在至少两个不同合法正有限 `dt` 下应产生
相同基础 intent。禁止使用 `dt` 偷偷实现 pitch 有限差分、filtering、slew-rate 或 output
shaping。

`dt=0`、负数、NaN 和正负 Inf 必须在 controller layer fail-close。

`reset()` 必须清除候选内部临时状态和命令/基线缓存，不复用上一场景 command，不设置 IMU
zero，不改变 Runtime authority，不清除 E-STOP/ERROR，也不访问硬件。瞬时 damping 原则上
不需要 pitch 历史；候选如需少量 task-local 状态，必须说明必要性并证明它不是 ALG-003
filtering 或其它未来能力。

## 12. Future-task boundary

ALG-002 明确禁止提前实现：

- **ALG-003**：deadband、filtering、low-pass、hysteresis、noise smoothing、temporal filter；
- **ALG-004**：slew-rate limiting、output shaping、dynamic saturation；
- **ALG-005**：`STABLE/DISTURBED/RECOVERING/SETTLING`、recovery state machine/timeout；
- **ALG-006**：motor/fan control allocation、allocation matrix、actuator priority；
- **ALG-007**：roll control 或 multi-axis recovery；
- **ALG-008**：完整 disturbance recovery 或动态恢复结论。

同时禁止 integral/accumulated error/windup、raw gyro axis/sign logic 和真实 actuator direction
mapping。必要输入检查、合法完整命令、safe-stop、reset 和纯软件测试 seam 不属于越界。

若未来实现发现必须改变 Flight API、Runtime、authority 或硬件 manager/driver，应停止普通
算法任务并拆分独立 API/architecture/safety review。
